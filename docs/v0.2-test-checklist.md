# v0.2.0 真人身份与 Session 验收

## 能力边界

本版本只保存真人身份和 Session，不创建 Run、Round、Segment，也不统计击杀、伤害、治疗或救援。

支持模式：

```text
coop
realism
versus
```

其他模式不创建玩家和 Session 记录。

## 1. 加载与初始写入

1. 运行 `scripts/deploy.ps1`。
2. 在游戏中加载 `coop` 地图并执行：

```text
sm plugins reload l4d2_player_stats
sm_lps_status
```

预期：

- 插件版本为 `0.2.0`；
- 数据库状态为 `ready`；
- `game_mode=coop`、`mode_family=pve`；
- 真人进入后 `active_sessions` 至少为 1；
- `pending_closed_sessions=0/256`。

## 2. 时间口径

依次测试：

1. 作为幸存者正常操作约 20 秒；
2. 进入观战或闲置约 10 秒；
3. 恢复操作约 10 秒；
4. 执行 `sm_lps_flush`；
5. 退出当前本地服务器，使 Session 关闭。

数据库中应满足：

```text
connected_seconds > active_play_seconds
status = closed
disconnect_reason = client_disconnect
```

死亡等待和感染者复活等待仍属于 active；纯观战和闲置不属于 active。

## 3. 跨地图与断线

- 正常换到同一战役下一张地图：同一个 `session_id` 继续更新。
- 断开后重新进入：创建新的 `session_id`。
- 从 `coop` 切换到 `realism`：Session 保持连续。
- 切换到不支持模式：当前 Session 以 `unsupported_mode` 关闭。
- 从不支持模式切回：创建新 Session。

## 4. Bot 和隐私

- Bot 不得出现在 `lps_players` 或 `lps_sessions`。
- `sm_lps_status` 和 SourceMod 正常日志不得显示玩家 IP。
- SQLite 中 Session 应保存去掉端口后的 IP；本地 listen server 使用 `127.0.0.1`。

## 5. 本地 SQLite 检查

关闭或离开本地服务器后运行：

```powershell
python .\scripts\inspect_sqlite.py "E:\SteamLibrary\steamapps\common\Left 4 Dead 2\left4dead2\addons\sourcemod\data\sqlite\l4d2_player_stats.sq3"
```

检查工具只显示 Session 状态和时间，不输出 IP。

## 6. 数据库故障

1. 在有人在线时让数据库暂时不可用；
2. 继续游玩并断开一名真人；
3. 恢复数据库或执行 `sm_lps_reconnect`；
4. 检查 closed Session 是否补写。

预期：

- 活跃 Session 保留 dirty 状态；
- 关闭 Session 进入有界内存队列；
- 数据库恢复后使用绝对快照补写；
- 队列最多保留 `sm_lps_closed_session_queue_limit` 条；
- 不创建本地失败数据文件或无限增长的专属日志。
