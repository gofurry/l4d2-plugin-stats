# v0.6.2 Versus Infected Class Breakdown Test Checklist

v0.6.2 继续使用未发布阶段的可重建数据库策略。旧 SQLite 没有职业子表，测试前必须在游戏完全关闭时备份并移走：

```text
left4dead2/addons/sourcemod/data/sqlite/l4d2_player_stats.sq3
```

插件重新加载后，`sm_lps_status` 应显示 `state=ready`、`schema=1/1`。

## 1. 最小本地场景

```text
map c5m1_waterfront versus
sv_cheats 1
sb_all_bot_game 1
```

以感染者身份完成第一半场的一部分即可，不要求打完整战役：

- [ ] 至少以两种不同职业成功实体化出生；
- [ ] 至少对一名 Bot 幸存者造成有效伤害；
- [ ] 如果条件允许，造成一次倒地或击杀；
- [ ] 执行 `sm_lps_flush`，等待数秒后退出游戏。

## 2. 数据库检查

```powershell
python scripts/inspect_sqlite.py "<SourceMod>/data/sqlite/l4d2_player_stats.sq3"
```

预期：

- `versus_infected_class_stats` 大于 0；
- `orphan_versus_infected_class_stats=0`；
- `invalid_versus_infected_class_stats=0`；
- `versus_infected_class_total_mismatches=0`；
- `recent_versus_infected_class_stats` 只出现 Smoker、Boomer、Hunter、Spitter、Jockey、Charger、Tank；
- 各职业的出生、真人/Bot 伤害、倒地和击杀之和分别等于同一 Segment 的感染者总计。

本地不需要强行覆盖全部七种职业。SQLite 集成测试已经覆盖 Smoker、Tank、绝对快照重试和合计一致性；所有职业的真实多人时序继续在 v0.7.0 灰度阶段复核。

## 3. 失败条件

出现以下任一情况时，v0.6.2 不通过：

- 插件加载或刷新时报缺少 `lps_versus_infected_class_stats`；
- 同一职业因周期刷新产生重复累计；
- Bot 感染者生成个人职业行；
- 未知职业创建动态 ID 或名称；
- 任一职业合计与感染者总计不一致。
