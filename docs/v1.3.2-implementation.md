# 2. Collector：新增 `fall_deaths`

v1.3.2 Collector 唯一新增的业务统计事实是：

```text
fall_deaths
```

## 2.1 Stats schema 6

PvE：

```text
lps_pve_segment_stats.fall_deaths BIGINT NULL
```

Versus Survivor：

```text
lps_versus_survivor_stats.fall_deaths BIGINT NULL
```

历史行：

```text
NULL = 当时未采集
```

v1.3.2 后新 Segment：

```text
0+ = 已采集
```

不得将旧数据迁移为真实 0。

## 2.2 判定语义

认证真人 Survivor 的有效 `player_death`：

```text
abort = false
```

且事件 `type` 包含：

```text
DMG_FALL
```

则：

```text
fall_deaths += 1
```

要求：

- PvE / Versus Survivor 同口径；
- Bot 不拥有该玩家统计；
- 不保存逐次坠落伤害；
- 不根据“最近几秒受过坠落伤害”猜测；
- 不新增 `FALL_DEATH` Incident；
- `fall_deaths` 是现有 `deaths` 的原因子集。

`doctor --deep`：

```text
fall_deaths IS NULL OR fall_deaths >= 0
fall_deaths <= deaths
```

# 3. Achievement 数据边界

Stats DB 只保存游戏事实。

Dashboard DB 保存：

- Achievement unlock；
- Achievement evaluator state；
- 历史 Backfill state；
- Badge Showcase。

不要把 Achievement 写回 Stats DB。

Achievement 不由 Collector 直接发放。

# 4. Dashboard schema 14

建议新增四张表。

## 4.1 `achievement_unlocks`

```text
steam_id
achievement_key
achievement_contract_version
unlocked_at
grant_kind
value_at_unlock
evidence_steam_id
seen_at
```

主键：

```text
(steam_id, achievement_key)
```

`grant_kind`：

```text
live
backfill
```

`unlocked_at` 定义：

> Dashboard 首次确认玩家已经满足该 Achievement 的时间。

它不是历史真实跨过阈值的精确时间。

## 4.2 `achievement_evaluation_state`

```text
steam_id PRIMARY KEY
achievement_contract_version
source_watermark
evaluated_at
```

Stats 数据没有变化时不得重复完整评估。

## 4.3 `player_badge_showcase`

```text
steam_id
slot
achievement_key
updated_at
```

主键：

```text
(steam_id, slot)
```

`slot` 仅允许：

```text
1..3
```

要求：

- 只能 Steam 登录本人修改；
- 只能选择自己已解锁的 Achievement；
- slot 1 是主 Badge。

## 4.4 `achievement_engine_state`

单例状态，例如：

```text
achievement_contract_version
global_source_watermark
backfill_cursor
backfill_complete
last_run_at
last_success_at
last_error
updated_at
```

用途：

- 自动 evaluator 恢复；
- 首次 Backfill 恢复；
- 管理页只读状态。

## 4.5 Dashboard schema 15：个人资料可见性

新增 `player_profile_visibility`，按 SteamID 保存公开的个人中心一级 Tab allowlist。没有设置记录时默认公开 `overview`、`analysis`、`relationships`；显式空数组表示全部关闭，未来新增 Tab 因不在 allowlist 中而默认不公开。本人访问不受公开 allowlist 限制，访客访问必须由服务端逐接口校验。

# 5. Achievement Contract v1

权威语义见：

```text
contracts/achievement-v1.md
```

必须遵守：

- 只支持单调指标；
- 所有条件统一为 `metric >= threshold`；
- metric 必须由 Go 白名单 resolver 实现；
- 不允许任意 SQL；
- 不允许用户/管理员手动刷新；
- 不允许手动领取；
- Achievement 一旦解锁，正常运行不自动撤销；
- 历史 `NULL` 代表“未采集”，不是 0；
- `public / mystery / secret` 三种可见性；
- 搞笑/负面 secret 不计入正常完成度。

# 6. 自动判定模型

## 6.1 后台增量 Evaluator

默认每 10 分钟运行。

禁止：

```text
扫描全部玩家 × 全部成就
```

应实现 bounded dirty-player discovery：

```text
ListAchievementDirtyPlayers(sinceWatermark, limit)
```

根据相关 Stats 表的 `last_saved_at` / source watermark 找出发生变化的 SteamID。

至少覆盖：

- Player Segment；
- PvE Segment Stats；
- PvE Equipment Stats / retention-safe aggregate；
- Versus Survivor Stats；
- Versus Infected Stats；
- Relationship actor / target；
- 其他本 Catalog 使用的永久事实。

## 6.2 玩家页自动补判

读取玩家资料 Header / Achievement Tab 前：

```text
player_source_watermark > achievement_evaluation_state.source_watermark
```

则自动评估当前玩家一次，然后再返回最新结果。

这不是“手动刷新”，UI 不提供刷新按钮。

## 6.3 首次历史 Backfill

v1.3.2 首次启动：

- 后台低优先级；
- bounded batch；
- 建议每批约 100 玩家；
- 可中断恢复；
- `achievement_engine_state.backfill_cursor` 保存进度；
- 正在访问的玩家优先通过按需补判完成。

历史补发：

```text
grant_kind = backfill
```

不得伪造真实历史解锁日期。

# 8. Retention Safety

Achievement progress 不得因为原始数据 retention 而下降。

要求：

- PvE / Versus Core Stats：永久 Segment stats；
- Assist：永久 Core Stats；
- Relationship：永久关系表 + permanent Player Segment；
- active play：permanent Player Segment；
- firearm headshot kills：必须使用 retention-safe lifetime / aggregate read model，不能只扫还未清理的装备明细；
- Incident 不参与 v1.3.2 首批 Achievement。
