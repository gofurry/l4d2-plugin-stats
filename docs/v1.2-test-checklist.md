# v1.2 测试与验收清单

本清单验收 v1.2.0 的 Collector、Dashboard schema 10、Stats schema 3、Aggregate Contract v1，以及警报车、对抗机关互动和 Steam OpenID 本机代理配置。这些采集指标不进入首页或成就系统，对抗机关互动也不进入排行榜。

## 升级前

1. 停止 Dashboard，并执行 `l4d2-stats backup create --config ./config.yaml`。
2. MySQL/PostgreSQL 另用数据库原生工具备份 Stats DB。
3. 保存旧 `.smx`、Dashboard 二进制、配置和数据库备份。

## 静态与自动化测试

在仓库根目录执行：

```powershell
python scripts/test_sqlite_migration.py
python scripts/validate_versus_contract.py
powershell -ExecutionPolicy Bypass -File scripts/validate-migrations.ps1
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
```

在 `dashboard` 目录执行：

```powershell
go test ./...
go vet ./...
```

在 `dashboard/frontend` 目录执行：

```powershell
pnpm test
pnpm typecheck
pnpm lint
pnpm build
```

本地默认覆盖 SQLite；MySQL 8.4 与 PostgreSQL 17 的相同数据库契约测试由 `database-contract.yml` CI 矩阵执行。

## 数据库升级验收

1. 将三种驱动对应目录中的全部迁移文件一起部署，不能只复制 `0001_initial.sql`。
2. 加载采集器后执行 `sm_lps_status`，应显示 `version=1.2.0`、`state=ready`、`schema=3/3`。
3. 检查 `lps_schema_migrations` 同时存在版本 1、2 和 3。
4. 检查 PvE 与 Versus 幸存者统计表均有可空的 `car_alarms_triggered`；升级前的历史行应为 `NULL`。
5. 检查 Versus 幸存者统计表有可空的 `objective_interactions`；升级前的历史行应为 `NULL`。
6. 执行 `l4d2-stats doctor --deep --config ./config.yaml`，不得出现 error。

## 游戏内采集验收

1. 用真人幸存者在 `coop` 或 `realism` 触发一辆警报车，执行 `sm_lps_flush`；仅对应 PvE Segment 增加 1。
2. 在 `versus` 的幸存者半场触发警报车并刷新；仅对应 Versus 幸存者 Segment 增加 1。
3. 切到感染者、旁观者或使用 Bot 触发相关流程，计数不得增加。
4. 重复刷新和断线重连不得把绝对快照重复累加。
5. 在合作和对抗幸存者半场分别完成同一种白名单机关，两个模式各自 Segment 的 `objective_interactions` 增加 1；同一机关在同一 Round 重复输出不得重复计数。

可用以下查询抽查：

```sql
SELECT s.steam_id, p.car_alarms_triggered
FROM lps_pve_segment_stats p JOIN lps_player_segments s ON s.segment_id=p.segment_id
ORDER BY s.started_at DESC;

SELECT s.steam_id, p.car_alarms_triggered
FROM lps_versus_survivor_stats p JOIN lps_player_segments s ON s.segment_id=p.segment_id
ORDER BY s.started_at DESC;

SELECT s.steam_id, p.objective_interactions
FROM lps_versus_survivor_stats p JOIN lps_player_segments s ON s.segment_id=p.segment_id
ORDER BY s.started_at DESC;
```

## Dashboard 验收

1. `l4d2-stats version` 输出 `1.2.0`，Dashboard DB 自动升级到 schema 10，`/api/v1/health/ready` 返回 ready 且 Stats schema 为 3。
2. 在后台 Steam 登录设置填写本机 HTTP 代理端口后完成登录；代理日志应只看到发往 Steam OpenID 的请求，清空端口后恢复直连。
3. 玩家个人页的 PvE 与对抗幸存者“互动与事件”分别显示正确计数，时间、服务器和 PvE 模式筛选有效。
4. 排行榜可分别选择 PvE/对抗幸存者的“触发警报车”，全服 Top 顺序按次数降序，相同次数按 SteamID 稳定排序；时间、服务器、指定玩家和“我的排名”筛选有效。
5. 首页概览与在线玩家预览不得出现警报车指标；代码和界面不得出现相关成就。
6. 机关互动不得出现在首页、排行榜或成就内容中。
7. 最近记录的 Session 与章节列表中，日期保持单行、时长与状态右对齐；窄屏切为单列，手机端只保留主字段与状态且不横向溢出。
8. `diagnostics export` 即使 deep doctor 有 warning 也能生成脱敏诊断包。

验收失败时停止新二进制，使用升级前归档执行 `backup restore`，并恢复旧采集器；Stats schema 已升级时不能只回滚二进制而保留不匹配的数据库。
