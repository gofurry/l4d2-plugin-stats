# v1.2 测试与验收清单

本清单验收 v1.2.0 的 Collector、Dashboard schema 9、Stats schema 2、Aggregate Contract v1，以及新增的警报车事件指标。警报车指标不进入首页或成就系统。

## 升级前

1. 停止 Dashboard，并执行 `l4d2-stats backup create --config ./config.yaml`。
2. MySQL/PostgreSQL 另用数据库原生工具备份 Stats DB。
3. 保存旧 `.smx`、Dashboard 二进制、配置和数据库备份。

## 静态与自动化测试

在仓库根目录执行：

```powershell
python scripts/test_sqlite_migration.py
python scripts/validate_versus_contract.py
powershell -ExecutionPolicy Bypass -File scripts/validate-migrations.ps1
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
```

在 `dashboard` 目录执行：

```powershell
go test ./...
go vet ./...
```

在 `dashboard/frontend` 目录执行：

```powershell
pnpm test
pnpm typecheck
pnpm lint
pnpm build
```

本地默认覆盖 SQLite；MySQL 8.4 与 PostgreSQL 17 的相同数据库契约测试由 `database-contract.yml` CI 矩阵执行。

## 数据库升级验收

1. 将三种驱动对应目录中的全部迁移文件一起部署，不能只复制 `0001_initial.sql`。
2. 加载采集器后执行 `sm_lps_status`，应显示 `version=1.2.0`、`state=ready`、`schema=2/2`。
3. 检查 `lps_schema_migrations` 同时存在版本 1 和 2。
4. 检查 PvE 与 Versus 幸存者统计表均有可空的 `car_alarms_triggered`；升级前的历史行应为 `NULL`。
5. 执行 `l4d2-stats doctor --deep --config ./config.yaml`，不得出现 error。

## 游戏内采集验收

1. 用真人幸存者在 `coop` 或 `realism` 触发一辆警报车，执行 `sm_lps_flush`；仅对应 PvE Segment 增加 1。
2. 在 `versus` 的幸存者半场触发警报车并刷新；仅对应 Versus 幸存者 Segment 增加 1。
3. 切到感染者、旁观者或使用 Bot 触发相关流程，计数不得增加。
4. 重复刷新和断线重连不得把绝对快照重复累加。

可用以下查询抽查：

```sql
SELECT s.steam_id, p.car_alarms_triggered
FROM lps_pve_segment_stats p JOIN lps_player_segments s ON s.segment_id=p.segment_id
ORDER BY s.started_at DESC;

SELECT s.steam_id, p.car_alarms_triggered
FROM lps_versus_survivor_stats p JOIN lps_player_segments s ON s.segment_id=p.segment_id
ORDER BY s.started_at DESC;
```

## Dashboard 验收

1. `l4d2-stats version` 输出 `1.2.0`，`/api/v1/health/ready` 返回 ready 且 Stats schema 为 2。
2. 玩家个人页的 PvE“互动与事件”和对抗幸存者“事件”分别显示正确计数，时间、服务器和 PvE 模式筛选有效。
3. 排行榜可分别选择 PvE/对抗幸存者的“触发警报车”，全服 Top 顺序按次数降序，相同次数按 SteamID 稳定排序；时间、服务器、指定玩家和“我的排名”筛选有效。
4. 首页概览与在线玩家预览不得出现警报车指标；代码和界面不得出现相关成就。
5. `diagnostics export` 即使 deep doctor 有 warning 也能生成脱敏诊断包。

验收失败时停止新二进制，使用升级前归档执行 `backup restore`，并恢复旧采集器；Stats schema 已升级时不能只回滚二进制而保留不匹配的数据库。
