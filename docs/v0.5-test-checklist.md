# v0.5 PvE 治疗与章节统计本地验收

本文用于在单人 listen server 上验收 v0.5.0。所有新增字段仍归属 `coop` / `realism` 的真人幸存者 Segment，数据库 schema 与 `stats_version=1` 均不变。

## 1. 准备

1. 执行 `scripts/deploy.ps1`。
2. 进入 `coop`，执行 `sm plugins reload l4d2_player_stats`。
3. 执行 `sm_lps_status`，确认版本为 `0.5.0`、数据库为 `ready` 且 `active_pve_stats=1`。

## 2. 医疗包自疗

让真人幸存者受到足够伤害，再成功对自己使用一次医疗包。

预期：

- `medkits_self +1`；
- `heal_self` 增加本次 `heal_success.health_restored` 报告的实际真实生命；
- 治疗未完成或被打断时不增加次数和治疗量；
- 治疗量不是医疗包理论固定值，不包含临时生命。

## 3. 医疗包治疗队友

让一个幸存者 Bot 受伤，并由真人成功为其使用一次医疗包。

预期：

- 真人的 `medkits_others +1`；
- 真人的 `heal_others` 增加实际恢复的真实生命；
- Bot 不创建个人统计行；
- Bot 给真人治疗时，不把治疗行为转移给真人。

## 4. 止痛药、肾上腺素与临时生命

在总生命低于上限时分别使用一次止痛药和肾上腺素。

预期：

- `pills +1`、`adrenaline +1`；
- `temp_health` 增加两次物品实际带来的临时生命；
- 临时生命接近上限时只记录实际新增量，不盲目记录默认 ConVar 数值；
- 物品使用事件若缺少可靠的使用前生命快照，只记录使用次数，不猜测治疗量。

说明：采集器在玩家指令执行前保存总有效生命，并在物品成功事件后读取结果；必要时延迟到下一帧，以兼容事件在生命更新前后触发的差异。

## 5. 正常章节完成

正常完成一个非结局章节并进入下一张地图，在换图前后不要重载插件。

预期上一章结束时仍在操作幸存者的真人 Segment：

- `chapters +1`；
- 存活（包括倒地但未真正死亡）时 `chapters_alive +1`；
- 真正死亡但仍属于当前参赛者时 `chapters_dead +1`；
- `chapters_alive + chapters_dead = chapters`；
- 团灭失败、手动换图和放弃章节不增加这些字段。

## 6. 战役完成

正常完成最终章节。

预期最终章节对应的真人 Segment：

- 正常增加一次章节参与及 alive/dead 完成结果；
- `campaigns +1`；
- 非结局章节、团灭和手动换图不会增加 `campaigns`。

## 7. 参与边界

- 中途加入只可能获得加入后完成的章节，不补记之前章节；
- 章节结束时处于观战或闲置状态的真人不获得章节完成；
- Bot 没有章节或战役成绩；
- 一章内多次闲置/接管产生多个 Segment 时，章节成绩只落到结束时有效的一个 Segment。

## 8. SQLite 检查

测试后执行：

```text
sm_lps_flush
```

退出游戏，再运行：

```powershell
python scripts/inspect_sqlite.py "<SourceMod SQLite 文件路径>"
```

通过标准：

- `integrity=ok`；
- `orphan_pve_stats=0`、`invalid_pve_stats=0`；
- 治疗量、临时生命和章节字段符合本次人工操作；
- 连续刷新不会让任何计数翻倍；
- 旧 v0.4 记录的新字段保持 0，不需要迁移或回填。
