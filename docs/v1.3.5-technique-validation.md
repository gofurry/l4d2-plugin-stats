# v1.3.5 技巧判定实机验证

状态：尚未完成真实游戏验证。本文是发布前必须执行的验证矩阵，不代表 Hunter Skeet 或 Charger Level 已在生产环境确认。

## 固定环境

- Left 4 Dead 2 build：`10097`；
- SourceMod：生产兼容线 1.12；
- Collector：v1.3.5、Stats schema 7；
- 分别覆盖 `coop`/`realism` 的 AI 特感与 `versus` 的真人/Bot 特感（能够安排时）；
- 每项开始前创建新 Segment，记录该玩家五个新字段的基线，动作后执行 `sm_lps_flush` 并查询对应 Segment；
- 同时确认 SourceMod 错误日志没有永久输出逐事件、聊天正文或玩家 IP。

当前检测器以事件驱动的短生命周期为第一重证据，并在最终击杀时保守检查 Hunter 的空中扑击属性或 Charger 的冲锋属性。成功控制、落地/扑击结束、冲锋结束、撞击/带人、死亡、换队、换职业、断线、Round 结束、模式变化和客户端复用都会使 episode 失效。build 10097 的真实事件先后顺序与属性可见时机必须由本矩阵确认；属性缺失或顺序冲突时应记录精确事件场景并保持“不计数”，不得放宽为时间窗猜测。

## Hunter Skeet

| # | 场景 | 期望 |
|---:|---|---|
| 1 | Hunter 起扑并在空中、开始控制前被真人幸存者最终击杀 | 最终击杀者 `hunter_skeets +1` |
| 2 | Hunter 起扑前已受伤，随后在有效空中扑击中被击杀 | `+1` |
| 3 | Hunter 已成功扑倒/控制幸存者后死亡 | 不增加 |
| 4 | Hunter 扑空并已落地，之后死亡 | 不增加 |
| 5 | Hunter 站立、蹲伏或仅蓄力时死亡 | 不增加 |
| 6 | 多名幸存者先后造成伤害，最后一名真人在有效扑击中完成击杀 | 只有最终击杀者 `+1` |
| 7 | 复现可能重叠的 ability/pounce/death 事件 | 恰好 `+1`，不得重复 |
| 8 | `coop`/`realism` 的 AI Hunter | 符合 1 时 `+1` |
| 9 | `versus` 的真人 Hunter 与 Bot Hunter（可安排时） | 符合 1 时各 `+1` |

额外观察：如果“空中击杀”没有增加，记录 `ability_use`、`pounce_end`/`pounce_stopped`、`lunge_pounce`、`player_death` 的相对顺序，以及死亡前 `m_hGroundEntity`/`m_isAttemptingToPounce` 是否仍可读。只允许使用临时、管理员可见且默认关闭的诊断，不得永久记录高频玩法事件。

## Charger Level

| # | 场景 | 期望 |
|---:|---|---|
| 1 | Charger 正在冲锋且尚未撞击/带人，真人幸存者用官方近战最终击杀 | 最终击杀者 `charger_levels +1` |
| 2 | Charger 冲锋前已被枪械削血，冲锋中由官方近战最终击杀 | `+1` |
| 3 | 站立或冲锋已经结束的 Charger 被近战击杀 | 不增加 |
| 4 | Charger 已成功撞击、带人或开始捶打后死亡 | 不增加 |
| 5 | 冲锋中被枪械最终击杀 | 不增加 |
| 6 | 冲锋中被链锯最终击杀 | 不增加 |
| 7 | 冲锋中被自定义/不在固定表内的近战最终击杀 | 不增加 |
| 8 | 复现 ability、charge start/end、impact/carry 与 death 重叠 | 有效动作恰好 `+1`，无效动作 0 |
| 9 | 分别在 PvE 与 Versus 进行（可安排时含真人/Bot Charger） | 口径一致 |

额外观察：若有效近战击杀未增加，记录 `ability_use`、`charger_charge_start/end`、`charger_impact`、`charger_carry_start`、`charger_pummel_start`、`player_death` 的顺序，以及死亡前 `m_isCharging` 是否仍可读。不要因为单个实测失败而改用“开始后 N 秒内死亡”一类不可靠启发式。

## 通过标准

1. 所有正例在 PvE/Versus 可执行范围内稳定增加一次；
2. 所有反例保持 0；
3. 多人伤害只归最终真人幸存者；
4. 重复/重叠事件、换队、重生、断线、Round/模式切换和客户端槽位复用均不产生幽灵计数；
5. 新 Segment 的值明确为 0 或正整数，升级前历史 Segment 仍为 `NULL`；
6. 完成并记录 build 10097 结果前，发布说明只能写“待实机验证”，不能宣称判定器已验证正确。
