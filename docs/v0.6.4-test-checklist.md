# v0.6.4 Versus Survivor Combat Detail Test Checklist

v0.6.4 在未公开发布阶段继续重写 `0001_initial.sql`，新增幸存者感染者职业明细表，
并扩展幸存者总表。旧 SQLite 不含这些结构，测试前必须在游戏完全关闭时备份并移走：

```text
left4dead2/addons/sourcemod/data/sqlite/l4d2_player_stats.sq3
```

重新部署插件和迁移文件后启动游戏，`sm_lps_status` 应显示 `state=ready`、
`schema=1/1`。首次创建应得到 14 张表和 9 个查询索引。

## 1. 最小本地场景

```text
map c5m1_waterfront versus
sv_cheats 1
sb_all_bot_game 1
```

以真人幸存者完成以下最小测试，不需要打完整战役：

- [ ] 击杀至少两种由 Bot 控制的普通特感，并分别造成有效伤害；
- [ ] 对 Bot Tank 造成有效伤害并完成击杀；
- [ ] 投出 Molotov、Pipe Bomb、Vomit Jar 各一次；
- [ ] 部署燃烧弹药包和高爆弹药包各一次；
- [ ] 执行 `sm_lps_flush`，等待数秒后退出游戏。

建议但不阻塞本地验收的技巧测试：

- 击杀 Witch，并检查 Witch 击杀和有效伤害；
- 单人完成 Witch 击杀，检查 `witch_solo_kills`；
- 满血单次伤害击杀 Witch，检查 `witch_oneshots`；
- 用官方近战武器切断控制自己的 Smoker 舌头；
- 摧毁 Tank 已投出的飞行石头。

## 2. 数据库检查

```powershell
python scripts/inspect_sqlite.py "<SourceMod>/data/sqlite/l4d2_player_stats.sq3"
```

预期健康项：

- `orphan_versus_survivor_class_stats=0`；
- `invalid_versus_survivor_stats=0`；
- `invalid_versus_survivor_class_stats=0`；
- `versus_survivor_class_total_mismatches=0`；
- `versus_side_mismatches=0`；
- `versus_mode_mismatches=0`；
- `dual_versus_stats=0`。

预期明细：

- `recent_versus_survivor_stats` 中投掷物和弹药包计数与实际操作一致；
- `recent_versus_survivor_infected_class_stats` 中出现测试过的职业；
- 本地 Bot 场景写入 `kills_bot`、`damage_bot`，不会错误写入真人控制列；
- 普通特感六职业合计等于幸存者总表的普通特感总计；
- Tank 职业行等于幸存者总表的 Tank 总计；
- 重复执行 `sm_lps_flush` 不会让绝对快照重复累计。

双方真人控制列、真人与 Bot 混合目标、多人同时攻击 Witch、换队和长时间负载继续
统一放在 v0.7.0 真实服务器灰度验收。

## 3. 排除项检查

v0.6.4 不应产生逐武器对抗表，也不应因为以下行为动态增加数据库维度：

- 枪械射击、命中、换弹或弹药消耗；
- 普通感染者受伤；
- 未知/第三方武器、近战和投掷物名称；
- Skeet、Level、Deadstop 等未纳入技巧。

## 4. 失败条件

出现以下任一情况时，v0.6.4 不通过：

- 同一击杀或伤害被重复累计；
- 真人/Bot 控制归属相反；
- 职业明细无法聚合回总表；
- 未执行保存便在伤害、投掷物或技巧事件中直接产生 SQL；
- 未知职业或设备创建无上限行；
- SourceMod 错误日志出现本插件的事件、SQL、实体或数组越界错误。
