# Dashboard 数据生命周期

## 数据边界

- Stats DB 是采集事实来源，`serve` 进程只读，不执行采集器迁移或清理。
- Dashboard DB 保存站点设置、管理员、服务器目录和可重建的公开查询聚合。
- 公开 API 不读取或返回 Session IP、boot ID、内部数据库主键、DSN 或管理员数据。
- PvE 只包含 `coop`/`realism` 幸存者数据；Versus 的幸存者和感染者分别聚合。

## 当前读模型

Dashboard 每 10 分钟从 Stats DB 构建一次 UTC 日聚合，覆盖：

- Session 数、连接时间和实际操作时间；
- PvE 战斗、生存、团队、治疗、章节、技巧和目标互动；
- PvE 的 40 个固定装备桶；
- Versus 幸存者总计和被击杀感染者职业；
- Versus 感染者总计、职业控制、技能命中与技能伤害。

快照在 Dashboard SQLite 的单个事务中整体替换。读取失败或写入失败时保留上一份完整快照，原始 Stats DB 不受影响。可使用：

```text
l4d2-stats aggregate status
l4d2-stats aggregate rebuild
l4d2-stats retention plan
```

`retention plan` 只预估候选行，当前没有删除能力。

## 保留策略

| 数据 | 当前策略 | 未来允许的策略 |
|---|---|---|
| 玩家身份 | 永久保留 | 不删除 |
| Session、连接时间、实际操作时间、IP | 永久保留 | 不删除 |
| Run、Round、对局比分和胜负 | 永久保留 | 不删除 |
| PvE/Versus Segment 总计 | 永久保留 | 聚合稳定后仅考虑清理 365 天前明细 |
| 装备与职业细分 | 永久保留 | 聚合稳定后仅考虑清理 180 天前明细 |
| Dashboard 日聚合 | 当前完整重建 | 增量阶段保留最近 365 天，更早数据折叠为终身/月度汇总 |
| 应用日志 | Lumberjack 限量轮转 | 保持有界 |
| 内存缓存 | 固定容量和过期时间 | 保持有界 |

## 启用清理前的硬条件

未来的清理命令必须同时满足：

1. 聚合水位覆盖待清理范围；
2. 聚合与原始表按日期、玩家和指标抽样对账一致；
3. 生成包含范围、数量、水位和校验和的清理清单；
4. 由独立维护命令显式执行，网页服务仍使用只读 Stats DB；
5. 默认 dry-run，必须显式确认；
6. 分小批事务执行，失败可停止且不影响身份、Session、Run、Round 和比赛结果。

在这些条件完成前，扩大磁盘容量或归档整个数据库文件，不能直接删除原始行。
