# v0.4 PvE 核心统计本地验收

本文用于在单人 listen server 上验收 v0.4.0。统计只在 `coop` 与 `realism` 中进入 `lps_pve_segment_stats`；Versus 统计保留到 v0.6.0。

## 1. 准备

1. 执行 `scripts/deploy.ps1`。
2. 以 `coop` 启动一张熟悉的地图并确认真人正在操作幸存者。
3. 执行 `sm plugins reload l4d2_player_stats`，再执行 `sm_lps_status`。

预期：

- 插件版本为 `0.4.0`，数据库状态为 `ready`；
- `active_segments=1` 且 `active_pve_stats=1`；
- `pending_closed_pve_stats=0/512`；
- Bot 不会创建自己的 Player、Session、Segment 或 PvE 统计行。

## 2. 基础击杀与伤害

正常游玩一小段，至少完成以下动作：

- 击杀若干普通感染者；
- 击杀一只六种普通特感之一；
- 对该特感造成伤害；
- 被感染者造成伤害。

执行 `sm_lps_flush`，等待数秒后退出并运行：

```powershell
python scripts/inspect_sqlite.py "<SourceMod SQLite 文件路径>"
```

预期最新 `recent_pve_stats` 中：

- `common`、`special`、`damage_si` 和 `damage_taken` 大于 0；
- 击杀只归最后一击；
- `damage_si` 是目标实际损失的生命，不按武器面板伤害累计溢出值；
- 普通感染者只统计击杀，不统计对其造成的伤害。

## 3. Tank 与 Witch

分别对 Tank 和 Witch 造成伤害并完成最后击杀，然后刷新并检查数据库。

预期：

- `tank=1`、`witch=1`；
- `damage_tank` 与 `damage_witch` 大于 0；
- 对已只剩少量生命的目标打出高伤害时，记录值不会超过该目标命中前的剩余生命；
- Bot 或环境完成最后一击时，不给真人增加对应击杀。

## 4. 友伤拆分

这部分在单人环境至少能验证对 Bot 友伤：

1. 对一个幸存者 Bot 造成可见的实际伤害；
2. 刷新后确认 `ff_bot` 增加；
3. 确认自伤、坠落、溺水和地图伤害不会进入友伤。

`ff_human` 与 `ff_taken` 需要第二名真人参与，转移到 v0.7.0 多人发布加固验收；它们不阻塞本地 v0.4.0。

## 5. 倒地、死亡与救援

在可操作条件下逐项验证：

- 真人倒地：`incaps +1`；
- 真人真正死亡：`deaths +1`；
- 真人救起倒地队友：救援者 `revives +1`，被救者 `rescues_received +1`；
- 真人拉起挂边队友：救援者 `ledge +1`，被救者 `rescues_received +1`；
- 真人用电击器复活队友：救援者 `defib +1`，被救者 `rescues_received +1`。

单人无法稳定完成的真人对真人项目保留到 v0.7.0，不阻塞本阶段。

## 6. Segment 与模式边界

1. 在一个章节中产生统计并执行 `sm_lps_flush`；
2. 正常进入下一章并继续产生统计；
3. 再次刷新、退出并检查数据库；
4. 分别进入 `versus` 和一个不支持模式，确认不会新增 PvE 统计行。

预期：

- 两章的统计分别归属各自的 Segment，不会跨 Segment 累加；
- `coop` 与 `realism` 都写入 PvE 表，并能通过 `lps_runs.game_mode` 区分；
- Versus 与不支持模式不写入 `lps_pve_segment_stats`；
- 检查工具显示 `orphan_pve_stats=0`、`invalid_pve_stats=0`。

## 7. 刷新与恢复

- 同一 Segment 连续执行两次 `sm_lps_flush`，数据库结果不得翻倍；
- 统计保存使用绝对快照，不使用数据库增量累加；
- 断开数据库后产生统计，再恢复连接并刷新，应写入当前完整快照；
- closed PvE 快照使用 `sm_lps_closed_lifecycle_queue_limit` 的同一有界上限，满时只写一条受限错误，不生成本地事件日志或 spool 文件。

## 8. 本地通过标准

本地 v0.4.0 最小通过条件：

- 普通感染者/特感击杀、特感有效伤害和感染者承伤数据合理；
- Tank/Witch 至少各验证一次伤害和最后击杀；
- 对 Bot 友伤可以正确写入且重复刷新不会翻倍；
- 两个正常章节分别生成 PvE 统计行；
- SQLite `integrity=ok`，所有 orphan、invalid 与 mismatch 检查均为 0。

真人友伤、真人救援、电击器复活及数据库故障期间断线等多人边界转移到 v0.7.0。
