# v0.6.0 Versus Core Statistics Test Checklist

v0.6.0 的代码、SourcePawn 编译、SQLite 绝对快照和 Bot 上下半场测试可在本地完成。单人 listen server 仍无法等价验证双方真人、换队、Tank 交接和重连；这些项目统一延期到 v0.7.0 的综合服务器灰度阶段。

## 1. 测试范围

本轮只验收：

- 真人幸存者与真人感染者的 Segment 归属；
- 幸存者对真人/Bot 特感和 Tank 的击杀、有效伤害；
- 幸存者普通感染者击杀、感染者承伤、真人/Bot 友伤；
- 幸存者倒地、死亡、救援、治疗和临时生命；
- 真人感染者有效出生，以及对真人/Bot 幸存者的伤害、倒地和击杀；
- 半场切换、换队、闲置/旁观、重连、中途加入和 Tank 交接后的数据边界。

本轮不验收推进分、稳定队伍、半场胜负、最终胜负、MVP、感染者职业明细或逐武器明细。

## 2. 部署前准备

1. 备份现有数据库和 SourceMod 错误日志。
2. 为测试实例配置唯一且稳定的 `sm_lps_server_key`。
3. 确认 `sm_lps_versus_stats_enabled "1"`；该开关以新 Segment 为边界生效。
4. 加载插件后由 root 管理员执行：

   ```text
   sm_lps_status
   ```

5. 确认状态为 `ready`，模式为 `versus`，schema 为 `1/1`，关闭队列没有持续增长。

当前数据库已经预留 `lps_versus_survivor_stats` 和 `lps_versus_infected_stats`，升级 v0.6.0 不需要清空 SQLite，也不需要新增迁移。

## 3. 本地 Bot 对抗与跨图回归

本地无需打完整战役，只需完成一张地图的两个半场并进入下一张地图：

```text
map c5m1_waterfront versus
sv_cheats 1
sb_all_bot_game 1
```

- [x] 第一半场以感染者身份产生有效出生和对 Bot 幸存者伤害。
- [x] 第二半场以幸存者身份产生普通感染者击杀、Bot 特感伤害/击杀和感染者承伤。
- [x] 两个半场分别写入 infected/survivor 统计表，所有数据库一致性检查为 0。
- [ ] 正常进入 `c5m2_park` 后停留 10～20 秒，执行 `sm_lps_flush` 再退出。
- [ ] c5m1 half 1、c5m1 half 2 和 c5m2 half 1 共用一个 `run_id`。
- [ ] 三个 Round 的 `round_seq` 依次为 1、2、3；c5m2 为 `map_seq=2`、`half_no=1`。
- [ ] 换图前后共用一个 `session_id`；退出 c5m2 后该 Session 正常关闭。
- [ ] 退出 c5m2 后同一 Run 为 `abandoned`，`round_count=3`，而不是产生第二个 Run。

这组测试通过后即可继续本地可验证的 v0.6.x 功能，不需要完成整场五图战役。

## 4. 最小双方真人场景（延期至 v0.7.0）

至少安排两名真人，双方各一人；为了覆盖 Bot 拆分，建议保留部分 Bot。

### 第一半场

- [ ] 真人 A 作为幸存者击杀普通感染者。
- [ ] 真人 A 分别伤害并击杀一只真人特感和一只 Bot 特感。
- [ ] 真人 A 分别伤害真人 Tank 和 Bot Tank；能控制最后一击时再核对击杀字段。
- [ ] 真人 A 受到真人感染者和普通感染者伤害。
- [ ] 真人 A 对真人队友与 Bot 队友各造成少量友伤，并让真人队友对 A 造成友伤。
- [ ] 真人幸存者发生一次倒地、一次救起；条件允许时再测挂边和电击器。
- [ ] 真人幸存者完成自疗、治疗队友、使用止痛药和肾上腺素。
- [ ] 真人 B 作为感染者完成至少一次非 Ghost 的可操作出生。
- [ ] 真人 B 分别伤害真人和 Bot 幸存者。
- [ ] 真人 B 分别使真人和 Bot 幸存者倒地；能控制最后一击时再核对击杀字段。

### 第二半场

- [ ] 正常结束第一半场并让双方交换阵营。
- [ ] 重复少量幸存者和感染者动作，确认新 Segment 写入对应的新表。
- [ ] 确认第一半场的 Segment 没有继续增长。

## 5. 生命周期边界场景（延期至 v0.7.0）

这些场景可以分多场进行，不要求一次完成：

- [ ] 真人在幸存者、感染者和旁观者之间切换；每段有效操作创建独立 Segment。
- [ ] 幸存者闲置交给 Bot 后停止个人统计，重新接管后进入新 Segment。
- [ ] 真人中途加入当前半场，只记录加入后的动作。
- [ ] 真人真实断线并重连，不继承其他玩家槽位的数据。
- [ ] Tank 在真人、Bot 或另一名真人之间交接，伤害/出生/击杀不写给错误玩家。
- [ ] 半场重开产生新的 Round/Segment，不覆盖旧尝试。
- [ ] 正常换图后 Session 延续，但新地图产生新的 Round/Segment。
- [ ] 手动换图、插件重载或异常结束留下可解释的 `abandoned` 状态，不伪装完成。

## 6. 保存与数据库核对

完成动作后等待一次正常刷新，或由 root 管理员执行：

```text
sm_lps_flush
```

然后退出参与者或正常结束半场，再执行一次刷新。SQLite 可运行：

```powershell
python scripts/inspect_sqlite.py "<SourceMod>/data/sqlite/l4d2_player_stats.sq3"
```

必须满足：

- [ ] `orphan_versus_survivor_stats = 0`
- [ ] `orphan_versus_infected_stats = 0`
- [ ] `invalid_versus_survivor_stats = 0`
- [ ] `invalid_versus_infected_stats = 0`
- [ ] `versus_side_mismatches = 0`
- [ ] `versus_mode_mismatches = 0`
- [ ] `dual_versus_stats = 0`
- [ ] survivor Segment 只出现在 `lps_versus_survivor_stats`
- [ ] infected Segment 只出现在 `lps_versus_infected_stats`
- [ ] 重复执行 `sm_lps_flush` 不会重复累加同一批数值
- [ ] PvE 表不会出现这些 Versus Segment 的统计行

数值核对优先检查“方向和归属”而不是追求每场完全相同：伤害必须接近实际生命损失，溢出伤害不得放大结果；真人/Bot 拆分必须与当时的目标控制状态一致。

## 7. 灰度观察（延期至 v0.7.0）

建议先在一个综合服务器启用 3～7 天，再扩展部署：

- 每天保存一次 `sm_lps_status` 输出；
- 保留并检查 `addons/sourcemod/logs/errors_*.log`；
- 定期运行数据库检查工具；
- 记录发生异常时的地图、半场、玩家阵营、是否闲置/换队/Tank 交接；
- 不要开启逐事件调试日志，避免长期磁盘增长。

发现问题时保留数据库副本和对应 SourceMod 日志。真实多人问题集中在 v0.7.0 修复；本地可复现的数据损坏或跨图错误仍应在继续扩展前修复。

## 8. 验收结论

以下条件全部成立后，Versus 采集器才能标记为“真实服务器验收完成”：

- 双方真人至少完成一个包含两个半场的对抗地图；
- 生命周期边界至少覆盖换队、中途加入、断线重连和 Tank 交接；
- 数据库健康检查全部为 0；
- 没有持续增长的关闭队列、重复统计或 SourceMod 运行错误；
- 数据拥有者、真人/Bot 拆分和半场归属可以由人工复核解释。
