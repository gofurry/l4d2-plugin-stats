# v1.3.1 测试与验收清单

本清单验收 Collector/Dashboard `1.3.1`、Stats schema 5、Player Relationship Contract v1、Assist Contract v1，以及 Incident Contract v1 的 append-only 事件 12-14。Dashboard schema 应保持 13，`stats_version=1` 与 Aggregate Contract v1 不变。

## 升级前

1. 执行 `l4d2-stats backup create --config ./config.yaml`；MySQL/PostgreSQL 另做原生备份。
2. 记录升级前 `sm_lps_status`、`l4d2-stats version` 和 `doctor --deep` 结果。
3. 保留 v1.3.0 二进制与 Stats schema 4 备份，作为完整回滚点。

## 迁移与健康检查

1. 重载采集器后，`sm_lps_status` 显示 `version=1.3.1`、`schema=5/5` 和 `state=ready`。
2. `l4d2-stats version` 输出 `1.3.1`，`doctor` 显示 Stats schema 5 / Dashboard schema 13。
3. `doctor --deep` 不报告 relationship、PvE Assist、Versus Assist 或 Incident 契约错误。
4. 抽查旧 Segment：新 Assist/Witch/黑白字段保持 `NULL`；新 Segment 从 0 开始采集。

## Player Relationship

1. 两名真人幸存者分别测试普通扶起、挂边救援、电击复活、为队友打包、黑白救回和友伤。
2. 测试击杀 Smoker/Hunter/Jockey/Charger 控制者并解救队友，确认职业与平均响应时间增加。
3. 确认自疗、Bot、感染者阵营、自己挣脱和无法确认 rescuer 时不产生关系行。
4. 个人页“玩家关系”能按时间、服务器、PvE/对抗过滤，分页与列排序改变后数据一致。
5. 点击玩家行时，抽屉分别显示“我 -> TA”与“TA -> 我”，并肩数据仍可从旧 Segment 派生。

## Assist

1. 对同一普通特感造成多次有效伤害，但由其他玩家/Bot/环境完成击杀：贡献者只获得 1 次 Assist。
2. 最后击杀者只获得 Kill，不同时获得 Assist；`abort=true`、未死亡、已断线贡献者不结算。
3. PvE 六职业 Assist 之和等于特感 Assist，Tank/Witch Assist 等于击杀参与减击杀。
4. 对抗普通特感与 Tank 按死亡时的真人/Bot controller 归类，Witch 的遭遇、击杀参与和派生 Assist 一致。
5. 个人页历史 `NULL` 显示“未采集”，新 Segment 的真实 0 显示 0。

## Incident 与前端

1. 惊扰 Witch、成功对玩家使用医疗包、完成白名单机关后，战局分析的组成、时间线和最近事件正确显示。
2. Witch 惊扰可关联对应 Spawn；医疗量不写入 `duration_ms` 或 `detail_flags`。
3. 首页玩家卡只有 8 个指标位，Boss 同一位分别显示 Tank/Witch，不显示关系或 Assist。
4. 最近记录的“加载更多”行内居中；桌面与窄屏下玩家卡关闭按钮都不遮挡玩家信息。
