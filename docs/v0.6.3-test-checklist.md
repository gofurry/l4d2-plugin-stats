# v0.6.3 Versus Control and Ability Test Checklist

v0.6.3 在未公开发布阶段继续重写 `0001_initial.sql`，为感染者职业行增加固定能力字段。
旧 SQLite 不含这些列，测试前必须在游戏完全关闭时备份并移走：

```text
left4dead2/addons/sourcemod/data/sqlite/l4d2_player_stats.sq3
```

重新部署插件和迁移文件后启动游戏，`sm_lps_status` 应显示 `state=ready`、
`schema=1/1`。

## 1. 最小本地场景

```text
map c5m1_waterfront versus
sv_cheats 1
sb_all_bot_game 1
```

以真人感染者完成以下测试。不要求打完整战役，也不要求一次覆盖全部四种控制职业：

- [ ] 使用 Smoker、Hunter、Jockey 或 Charger 中至少一种成功控制 Bot 幸存者；
- [ ] 让一次控制正常结束，并尽量维持数秒以便核对时长；
- [ ] 使用 Boomer 胆汁或死亡爆炸命中至少一名 Bot 幸存者；
- [ ] 使用 Spitter 酸液对至少一名 Bot 幸存者造成有效伤害；
- [ ] 执行 `sm_lps_flush`，等待数秒后退出游戏。

可选边界测试：

- Charger 搬运接捶打只算一次控制；
- 控制期间由控制者死亡、受害者死亡或 Round 结束来封口；
- Spitter 死亡后仍在地面的酸液继续归给原真人 Spitter；
- 普通胆汁罐不增加 Boomer 的能力命中人数。

## 2. 数据库检查

```powershell
python scripts/inspect_sqlite.py "<SourceMod>/data/sqlite/l4d2_player_stats.sq3"
```

预期：

- `invalid_versus_infected_class_stats=0`；
- `invalid_versus_infected_ability_stats=0`；
- `versus_infected_class_total_mismatches=0`；
- 控制职业行的 `controls_bot` 和 `control_seconds_bot` 大于 0；
- Boomer 行的 `ability_hits_bot` 大于 0；
- Spitter 行的 `ability_damage_bot` 大于 0，且不大于该行的 `damage_bot`；
- 其他职业不会错误填充不属于自己的能力字段；
- 重复执行 `sm_lps_flush` 不会让任何绝对快照重复累计。

本地 Bot 场景主要验证 Bot 目标列。真人目标列、换队、远端断线、多人同时控制和
20×20 长时间负载继续统一放在 v0.7.0 灰度验收。

## 3. 失败条件

出现以下任一情况时，v0.6.3 不通过：

- 同一次 Charger 搬运转捶打记录两次控制；
- 控制结束、死亡、换队或 Round 结束后时长没有封口；
- Boomer 命中数包含普通胆汁罐；
- Spitter 酸液伤害大于该职业总伤害，或死亡后的酸液归给其他职业；
- 周期刷新或手动刷新产生重复累计；
- SourceMod 错误日志出现本插件的事件、SQL 或数组越界错误。
