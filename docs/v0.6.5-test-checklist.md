# v0.6.5 Versus Scores and Match Results Test Checklist

v0.6.5 在未公开发布阶段继续重写 `0001_initial.sql`，新增两个结果表。旧 SQLite
没有这些结构，测试前需要在游戏完全关闭时备份并移走：

```text
left4dead2/addons/sourcemod/data/sqlite/l4d2_player_stats.sq3
```

重新部署插件和迁移后启动游戏，`sm_lps_status` 应显示 `state=ready`、`schema=1/1`。
首次创建应得到 16 张表和 9 个查询索引。

## 1. 最短核心验收：只打一张图

```text
map c5m1_waterfront versus
sv_cheats 1
sb_all_bot_game 1
```

完成同一章节的上下两个半场，然后执行：

```text
sm_lps_flush
```

等待数秒后检查 SQLite。这里不要求完成整个战役。

预期：

- `lps_versus_round_results` 为该地图产生两行；
- 两行对应 `half_no=1` 和 `half_no=2`；
- 两行的 `scoring_team_slot` 分别为 0 和 1，不能相同；
- `score_available=1`，计分槽位对应的 `team_N_map_score` 与游戏结算界面一致；
- `result_status=completed`；
- `lps_versus_run_results` 至少有一行 `active` 快照，累计分与当前战役比分一致；
- `winner_team_slot=-1`，因为普通章节结束还不能宣布整场胜者。

检查命令：

```powershell
python scripts/inspect_sqlite.py "<SourceMod>/data/sqlite/l4d2_player_stats.sq3"
```

健康项应全部为 0：

- `orphan_versus_round_results`；
- `orphan_versus_run_results`；
- `invalid_versus_round_results`；
- `invalid_versus_run_results`；
- `versus_result_status_mismatches`。
- `versus_scoring_slot_mismatches`。

`teams_flipped` 是原始诊断值，在本地 listen server 中允许两个半场都为 0；它不再作为
`scoring_team_slot` 的验收依据。

## 2. 推荐完整验收：战役最后两章

最终累计分和胜负无法通过普通章节的一部分验证，但无需重打一整个长战役。推荐从倒数
第二章开始，连续完成最后两章的上下半场，例如：

```text
map c5m4_quarter versus
sv_cheats 1
sb_all_bot_game 1
```

这样一次测试同时覆盖跨图累计分与 `versus_match_finished` 最终结果。只打最终章也能验证
最终事件和胜者派生，但不能证明前一章分数正确累加。

预期：

- `lps_runs.status=completed`；
- 对应 `lps_versus_run_results.result_status=completed`；
- 两个 `team_N_campaign_score` 与最终结算界面一致；
- 分高者的槽位写入 `winner_team_slot=0` 或 `1`；同分为 `2`；
- `raw_winner_team` 仅用于诊断，可以与逻辑槽位编号不同；
- `finalized_at` 非空。
- 第二章开始前后的累计分单调不减，最终值包含倒数第二章的分数。

## 3. 可选异常验收

完成一个半场后手动切换到无关地图，再刷新数据库：

- Run 和 Run 结果都应为 `abandoned`；
- `winner_team_slot=-1`；
- 已经完成的半场结果仍保留；
- 已观察到的累计分不会因新地图重置为更小值。

若重开相同半场，旧 Round 与对应结果都应被修正为 `abandoned`，新尝试使用新的
`round_id` 和更大的 `attempt_no`。

## 4. 失败条件

出现以下任一情况时 v0.6.5 不通过：

- 两个半场被写到同一个逻辑队伍槽位；
- 数据库分数与游戏结算界面不一致；
- 普通章节结束就产生最终胜者；
- 异常结束或分数不可用时仍宣布 0/1/平局胜者；
- 重复执行 `sm_lps_flush` 导致分数累加；
- SourceMod 错误日志出现 GameRules 属性、SQL、队列或数组错误。
