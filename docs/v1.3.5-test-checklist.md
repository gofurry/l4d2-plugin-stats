# v1.3.5 测试与验收清单

本清单验收 Collector/Dashboard `1.3.5`、Stats schema 7、Dashboard schema 23 和 Chat Audit schema 1。`stats_version=1`、Aggregate/Achievement/Incident/Relationship Contract v1 均保持不变。

## 1. 升级与数据库

1. 停止 Dashboard，备份 Collector、配置、Dashboard DB 和 Stats DB；常规备份有意不包含 `chat-audit.db`。
2. 同时部署新 `.smx` 和三种方言的 `0007_high_value_telemetry_chat.sql`。
3. `sm_lps_status` 应显示 `version=1.3.5`、`schema=7/7`、`state=ready`。
4. `l4d2-stats version` 应显示 `1.3.5`；`migrate status` 应显示 Dashboard schema 23；配置目录旁自动出现权限受限的 `chat-audit.db`，schema 为 1。
5. 从测试期 schema 22 升级时，既有百度 AK 与 cache secret 保持不变，独立 `enabled` 字段被干净移除，请求上限初始化为 2 QPS。
6. 旧 Segment 的五个新增字段保持 `NULL`，新 Segment 写入 0 或正整数。

## 2. Gameplay 新指标

- 触发游戏自身的保护队友奖励，PvE/Versus 真人幸存者分别增加 `teammate_protections`；Bot 作者、感染者或无有效 Segment 不增加。
- 同一次挂边重复事件只增加一个 `ledge_grabs`；在已挂边状态下新建 Segment 不增加。
- Tank 石块必须造成正有效伤害才增加 `tank_rock_hits_received`；同一石块对同一受害者最多一次。
- 个人 PvE/Versus 页面按 Support/Survival/Techniques 显示五项，历史空值显示“未采集”，不是 0。
- 全服排行榜只出现保护队友、Hunter Skeet、Charger Level；挂边和被石块命中没有公开榜，也不出现在 `/ingame`。
- Skeet/Level 必须另外完整执行 [`v1.3.5-technique-validation.md`](v1.3.5-technique-validation.md)；未执行前不得标记实机通过。

## 3. Chat Audit

1. 保持 `sm_lps_chat_audit_enabled 1`，让真人分别发送全局、队伍、`!command` 与 `/command` 消息；Bot 消息不得进入 outbox。
2. 在 Survival/Scavenge/自定义模式发送聊天：消息应被审计，但不得新建 gameplay Session/Run/Round/Segment/Stats。
3. 后台“审计 → 聊天记录”默认只查最近 24 小时；从右侧工具栏打开筛选，验证时间、server key、SteamID、昵称、地图、模式、阵营、频道、command-like、关键字和 boot ID，并验证上一页/页码/下一页游标导航。
4. 浏览器地址栏、访问日志和 export audit 不应出现搜索关键字或聊天正文。
5. CSV/JSONL 导出需要管理员与 CSRF；以 `= + - @` 开头的 CSV 文本前应增加单引号，JSONL 保留原始正文。
6. 把保留期从 30 天缩短到 7 天：存在受影响记录时先显示删除数量并要求确认；确认后先保存策略再按批清理。模拟清理中断时应提示清理待继续，刷新后仍显示 7 天，后续小时任务能继续完成；永久保留使用 `0`。
7. 数据增长页显示 DB 占用、消息数量、最老/最新时间、保留期、清理时间、摄取滞后、Collector 丢弃和已知 gap，不显示正文。
8. 制造 Dashboard 暂停超过 outbox 保留窗口的测试数据，恢复后必须报告 gap，不能声称完整。

## 4. Connections 与 GeoIP

1. 未配置 AK 时 GeoIP 不发出 provider 请求，普通首页/玩家/排行/`/ingame` 不出现 IP 或位置；后台不再存在启用/禁用开关。
2. 从连接记录右侧“密钥设置”保存百度 AK 与 1-3 QPS 后，读取接口只返回配置状态和掩码；空更新保留原 AK，明确“清除密钥”才删除并停止新请求。
3. 使用管理员提供的公开测试 IP 执行服务端测试；测试请求和后台队列必须共用同一无突发限速器。设置 2 QPS 时连续请求间隔约 500 ms，不得瞬间并发打满 provider。
4. 私有/回环/链路本地/文档地址应本地拒绝且不请求 provider。连接记录显示原始 Session IP 和已有城市级结果；相同 IP 命中 HMAC 缓存或 pending 去重，不重复消耗配额。
5. 等待成功缓存过期后确认后台按有界批次清理；清除 AK 后已有有效缓存仍可用于管理员审计展示，但不得再补查或刷新位置。
6. 从连接记录右侧工具栏打开筛选，构造前 100/200 条无匹配、后续记录才匹配的位置条件；第一页仍应找到后续匹配项，上一页/页码/下一页按最后实际扫描的原始行前进且不重不漏。缓存缺失时显示“部分位置仍在解析，请稍后刷新”，不得同步调用百度。
7. 模拟 timeout、错误 status、畸形 JSON、IPv6 未授权：正常 Dashboard 功能保持可用，错误状态不含 AK、完整请求 URL 或 raw IP。

## 5. 隐私、备份与诊断

- 未登录和非管理员请求所有 `/api/v1/admin/audit/*` 均被拒绝。
- `backup create` 归档不含 `chat-audit.db`；SQLite Stats 快照中 `lps_chat_outbox` 和 Session IP 为空，Dashboard 快照中百度 AK/cache secret 为空且 GeoIP cache 无记录，live Stats/Dashboard DB 均保持原值；恢复启动后生成不同的非空 cache secret。
- MySQL/PostgreSQL 原生备份可能包含 Session IP/outbox，应由管理员按隐私策略排除、加密或单独到期。
- `diagnostics export` 不含聊天正文、raw Chat DB、GeoIP AK 或 raw IP 列表，只含 schema/计数/健康状态。
- `doctor --deep` 检查五项非负/可空语义、Chat capture 计数/序列/唯一性、Chat DB schema/健康和 GeoIP 配置状态。
