# v0.3 Run / Round / Segment 本地验收

本文用于在单人 listen server 上验收 v0.3.0 生命周期。真人远端断线、多人换队和数据库故障期间断线补写已转移到 v0.7.0，不阻塞本阶段。

## 1. 准备

1. 执行 `scripts/deploy.ps1`。
2. 启动本地开发环境并进入 `coop` 第一章。
3. 执行 `sm plugins reload l4d2_player_stats`。
4. 执行 `sm_lps_status`。

预期：

- 版本为 `0.3.0`，数据库为 `ready`；
- `run` 和 `round` 都不是 `none`；
- PvE 的 `half=0`、`map_seq=1`、`attempt=1`；
- 真人正在操作幸存者时 `active_segments=1`。

## 2. SQLite 快照

执行 `sm_lps_flush`，等待成功写入后关闭游戏，再运行：

```powershell
python scripts/inspect_sqlite.py "<SourceMod SQLite 文件路径>"
```

预期至少存在一个 `active` Run、一个 `active` Round 和一个 `survivor` Segment。检查工具不会输出 IP 或 SteamID。

## 3. 观战、闲置与重新接管

按已有 v0.2 流程依次测试观战、闲置和重新接管，每一步等待 2～3 秒并执行 `sm_lps_status`：

- 进入观战或让 Bot 接管后，`active_segments` 变为 0，原 Segment 关闭；
- 重新操作幸存者后，创建新的 Segment，`active_segments` 回到 1；
- 同一 Round 中前后两个 Segment 的 `segment_id` 不同；
- 死亡等待、复活等待和等待救援本身不拆分 Segment。

## 4. PvE 团灭重试

让全队真正团灭并重试当前章节。重试后执行 `sm_lps_status` 和 `sm_lps_flush`。

预期：

- `run_id` 不变；
- 新 `round_id` 与失败前不同；
- `map_seq` 不变；
- `attempt` 从 1 增加到 2；
- 数据库中上一 Round 为 `failed`，新 Round 为 `active`；
- 新 Round 创建新的 Segment。

## 5. 正常章节推进

正常进入安全屋并等待下一章加载。不要使用 `changelevel` 代替正常过图。

预期：

- `run_id` 不变；
- 新章 `round_id` 改变；
- `map_seq` 增加 1；
- `attempt` 恢复为 1；
- 上一 Round 为 `completed`。

## 6. 手动换图

记录当前 `run_id`，执行一次手动 `changelevel` 到另一张地图。

预期：

- 旧 Round 和旧 Run 最终为 `abandoned`；
- 新地图创建新的 `run_id` 和 `round_id`；
- 新 Run 的 `map_seq=1`、`attempt=1`。

## 7. 精确模式切换

在 `coop` 与 `realism` 之间切换，再切换到不受支持模式。

预期：

- `coop` → `realism` 会放弃旧 Run，并创建精确模式为 `realism` 的新 Run；
- 切换到不受支持模式会关闭 Session、Run、Round 和 Segment；
- `sm_lps_status` 显示 `mode_family=unsupported`，且没有活动生命周期；
- 切回受支持模式后创建全新的生命周期。

## 8. 对抗半场

以 `versus` 启动一张地图，观察第一、第二半场并在每个半场开始后执行 `sm_lps_status`。

预期：

- 两个半场使用同一个 `run_id`；
- 两个半场使用不同 `round_id`；
- 第一半场 `half=1`，第二半场 `half=2`；
- 幸存者与感染者身份分别创建 `side=survivor` 和 `side=infected` 的 Segment；
- 同一半场重开时创建新 Round，`attempt` 增加，前一次 Round 修正为 `abandoned`。

本地单人无法充分验证多人对抗的远端断线和复杂换队时序；这些场景保留到 v0.7.0。

## 9. 结局与重载恢复

- 正常完成 PvE 结局后，Run 应为 `completed`；
- 在活动章节中重载插件，旧启动实例中的开放 Run、Round、Segment 和 Session 应在新连接注册时恢复为 `abandoned`；
- 新插件启动实例使用新的 `boot_id`，不会接续旧生命周期。

## 10. 日志与边界

- 正常运行不逐秒、不逐玩家写成功日志；
- `sm_lps_status` 和检查脚本不输出 IP；
- 数据库不可用时，closed Run、Round、Segment 共用有界内存队列；
- `sm_lps_closed_lifecycle_queue_limit` 默认 512，达到上限只输出一次受限错误，不创建本地 spool 文件。
