# v1.3.2 测试与验收清单

本清单验收 Collector/Dashboard `1.3.2`、Stats schema 6、Dashboard schema 15 和 Achievement Contract v1。既有 `stats_version=1`、Aggregate Contract v1、Incident Contract v1、Assist Contract v1 与 Player Relationship Contract v1 均保持不变。

## 1. 升级与健康检查

1. 升级前停止 Dashboard 并创建数据库/配置备份。
2. 使用 SourceMod 1.12 编译或安装采集器，重载后确认 `sm_lps_status` 显示 `version=1.3.2`、`schema=6/6`、`state=ready`。
3. 启动 Dashboard，确认 `l4d2-stats version` 输出 `1.3.2`，`doctor` 显示 Stats schema 6、Dashboard schema 15。
4. 执行 `doctor --deep`，确认没有 `fall_death_contract` 等 error。
5. 确认原有身份、会话、PvE、对抗、玩家关系和战局分析仍可查询。

## 2. 坠落死亡事实

1. 在升级前已存在的 PvE/对抗幸存者行中，确认 `fall_deaths IS NULL`，没有被回填为 0。
2. v1.3.2 创建的新 PvE 和对抗幸存者 Segment 即使没有坠落死亡，也应保存明确的 0。
3. 真人幸存者直接因坠落伤害死亡时，对应模式的 `deaths +1` 且 `fall_deaths +1`。
4. 普通感染者、特感、友伤或其他非 `DMG_FALL` 原因死亡时，只增加原有死亡口径，不增加 `fall_deaths`。
5. Bot、观战者、闲置玩家和未通过 Steam 验证的客户端不获得该玩家统计。
6. 所有新值满足 `0 <= fall_deaths <= deaths`，且没有新增坠落 Incident。

## 3. 自动判定与历史 Backfill

1. 首次启动后打开管理后台“数据增长监控”，只读成就引擎应显示 Contract v1、Catalog items、已判定玩家、待历史补判、上次运行/成功和最近错误。
2. Backfill 每批约 100 名玩家自动推进；重启 Dashboard 后应从保存的 cursor 继续，已插入 unlock 不重复。
3. 打开尚未被后台处理的玩家个人资料时，应自动补判一次再返回结果；页面不得出现刷新、重建或领取按钮。
4. 使用隔离的测试数据库分别准备冻结阈值的 `threshold - 1`、`threshold`、`threshold + 1`，确认只有达到阈值时解锁；一次跨过多个 Tier 时应一次确认所有已满足 Tier。
5. 历史补判记录为 `backfill`，在线增量确认为 `live`；`unlocked_at` 是 Dashboard 首次确认时间，不伪造历史日期。
6. 聚合尚未覆盖最新装备事实时，依赖受支持枪械爆头数的成就应等待聚合追上，不用旧水位提前确认。
7. 已解锁成就不会因原始明细保留清理、统计暂时不可用或后续启动而撤销。

## 4. 可见性与完成度

1. 未解锁 public 显示真实名称、说明、阈值与进度；已解锁后显示确认时间和全服解锁率。
2. 未解锁 mystery 只显示 `???`、`隐藏成就`/条件尚未发现，不返回真实 key、artwork、阈值或进度；多个 mystery 占位不能合并。
3. 未解锁 secret 完全不出现在公开结果；解锁后才出现，且计入“发现彩蛋”而不进入正常完成度分母/分子。
4. 对有证据搭档的关系成就，确认同值时按共同时间、共同对局数、SteamID64 的冻结顺序稳定选取搭档。
5. 同一玩家和 achievement key 重复判定不会产生重复 unlock。

## 5. 个人页、徽章与玩家卡片

1. 个人中心页头显示最多 3 枚展示徽章、正常成就完成数和发现彩蛋数；点击摘要进入“成就”一级标签。
2. “成就”标签按类别展示冻结目录；Tier、锁定、mystery、secret、空数据和窄屏布局均清晰可读。
3. Steam 登录且查看自己时，最多选择 3 个已解锁成就作为徽章；不能选择未解锁成就，也不能修改其他玩家展示位。
4. “展示徽章/取消展示”按钮在未获编辑授权时仍可见；点击后必须重新经过 Steam OpenID，成功后返回个人页“成就”标签并获得最多 10 分钟的编辑窗口。
5. 修改浏览器 localStorage 中保存的查询 SteamID、伪造其他玩家 SteamID、缺少或篡改身份/编辑 Cookie，都不能修改徽章；跨站 Origin 写请求必须返回 403。
6. 未手动配置时自动回退到最近 3 个计入完成度的解锁；secret 不参与自动回退，但已解锁 secret 可手动展示。
7. 玩家 Preview 只在名称旁展示主徽章，不显示完成度、彩蛋数、其他徽章或成就进度；个人页和 Preview 徽章悬停均显示成就名称。
8. 成就分类栏位于进度卡片底部；完成度、最近解锁和发现彩蛋保持可见，进度值使用完整数字而非 `1万`/`10K` 等缩写。
9. 首次看到 live 解锁时逐项提示 `🏆 解锁新成就：XXXX`；一次历史补判多项只汇总提示 `🏆 已确认 N 项历史成就`，刷新后不重复提示。

## 6. 个人资料可见性

1. 未保存设置的玩家默认只向访客显示“概览”“分析”“玩家关系”，本人登录查看时仍显示全部业务 Tab 和仅本人可见的“设置”。
2. 分别开启 PvE、PvE 明细、对抗四项、最近记录和成就，使用未登录浏览器确认只出现已开启 Tab；直接访问隐藏 Tab 的 URL 应落到第一个公开 Tab。
3. 只公开 PvE 概览时，PvE 明细接口返回 403；只公开 PvE 明细时，响应不得包含 PvE 概览总计。对抗幸存者/感染者及各自明细同样互不泄露。
4. 关闭“成就”后，访客不能读取成就和徽章接口，玩家 Preview 不显示主徽章；玩家卡片的既有其他内容保持不变。
5. 关闭全部栏目后，访客只看到玩家名称、SteamID 和未公开提示；本人仍能查看并恢复设置。
6. 匿名、伪造其他 SteamID、篡改 Cookie 或跨站 Origin 的保存请求均失败；修改 localStorage 不获得本人权限。

## 7. Artwork 与构建

1. `pnpm build:achievement-atlas` 必须验证恰好 26 个 256×256 透明 WebP source，无缺失、额外、重复或非法尺寸。
2. 输出必须固定为 768×640、6×5 网格、128×128 tile 的单张 WebP atlas，并生成 TypeScript 坐标；连续两次构建 SHA-256 相同。
3. Tier I/II/III/IV 外框分别可区分，锁定 public 使用灰暗 artwork，mystery 不加载真实 sprite。
4. 执行 `pnpm test`、`pnpm typecheck`、`pnpm lint` 和 `pnpm build`，确认前端生产产物写入 `dashboard/web/dist` 并能由 Go 二进制加载。

## 8. 最终回归

1. 执行 `go test ./...`、`go vet ./...`、三数据库 migration 静态校验、SQLite migration/contract 测试和 SourcePawn 1.12 完整编译。
2. 检查个人页其他标签、Steam OpenID、玩家预览、排行榜、战局分析、聚合和原始数据清理没有行为回归。
3. 最终执行 `git diff --check`，确认未提交 `.smx`、本地配置、数据库、日志、Token、Cookie、DSN 或密码。
