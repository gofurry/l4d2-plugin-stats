# v0.5.1 PvE 扩展统计测试清单

本清单用于验收固定设备明细、特感职业、控制/解救、Boss 参与、技巧统计和弹药升级包部署。

## 0. 测试前重建数据库

v0.5.1 仍处于未发布阶段，直接重写了 `0001_initial.sql`。旧 SQLite 已记录迁移版本 1，不会自动获得新列。

1. 完全关闭游戏。
2. 将现有 `addons/sourcemod/data/sqlite/l4d2_player_stats.sq3` 移到带日期的备份目录，或在不需要旧数据时删除。
3. 重新构建并部署插件与迁移。
4. 启动本地 `coop`，确认 `sm_lps_status` 显示 `version=0.5.1`、`state=ready`、`schema=1/1`。

正式发布后不得继续修改已经应用的 `0001`；后续结构变化必须新建迁移。

## 1. 自动验证

在仓库根目录执行：

```powershell
.\scripts\build.ps1
python .\scripts\test_sqlite_migration.py
```

预期：

- SourcePawn 编译无 error 和 warning；
- 三种迁移通过结构校验；
- SQLite 显示 19 statements、12 tables、7 indexes。

## 2. 普通特感职业

分别击杀 Smoker、Boomer、Hunter、Spitter、Jockey、Charger，并在每次测试后执行：

```text
sm_lps_flush
```

用检查工具确认：

- 各职业 `*_kills` 和 `damage_to_*` 进入正确字段；
- 六个职业击杀和等于 `special_kills`；
- 六个职业伤害和等于 `damage_to_special`；
- Tank 不进入普通特感职业字段。

## 3. 枪械、近战和 Other Firearm

至少使用一把官方枪械、一把官方近战和训练图提供的一把自定义枪械：

- 官方枪械生成自己的固定 `equipment_id` 行；
- 官方近战生成自己的固定行；
- 自定义枪械只生成 `equipment_id=1` 的 `Other Firearm` 行；
- 多种自定义枪械仍只产生同一个 `Other Firearm` 行；
- 自定义近战不产生设备行；
- 枪械射击数、换弹和弹药消耗不会增加 `actions`；
- 近战挥砍、命中和斩首没有独立字段；
- 只有枪械击杀可以增加 `headshot_kills`。

## 4. 投掷物

分别投掷 Molotov、Pipe Bomb 和 Vomit Jar：

- 每次成功投掷使对应设备行的 `actions` 增加 1；
- 可直接归属的特感/Tank/Witch 击杀与伤害进入对应设备行；
- Vomit Jar 引发的后续普通感染者围攻不推算成玩家击杀；
- 自定义投掷物不产生动态设备行。

## 5. 控制与团队解救

让 Smoker、Hunter、Jockey、Charger 分别成功控制真人幸存者：

- 被控制者相应 `*_controls_received` 增加；
- 控制结束后相应 `*_controlled_seconds` 增加；
- 另一名真人明确结束控制时，解救者相应 `*_saves` 增加；
- 自己挣脱不增加团队解救；
- 无法找到可靠解救者的结束事件不产生猜测数据。

本地单人可以验收“受控次数/时长”；真人队友解救保留到多人或独立服务器环境。

## 6. 技巧与 Boss 参与

- 本人使用官方近战切断控制自己的 Smoker 舌头：`melee_tongue_self_cuts +1`；
- 替队友切舌：该技巧字段不增加；
- 使用枪械在空中摧毁 Tank 石头：`tank_rocks_destroyed +1`；
- 参与伤害一只 Tank 并将其击杀：`tank_encounters +1`、`tank_kill_participations +1`；
- 单人从头到尾击杀 Witch：`witch_encounters +1`、`witch_kill_participations +1`、`witch_solo_kills +1`；
- 游戏事件判定为一击杀 Witch 时：`witch_oneshots +1`；
- 多名真人都伤害 Witch 时，不增加 `witch_solo_kills`。

## 7. 弹药升级包

分别部署燃烧弹药包和高爆弹药包：

- `incendiary_packs_deployed` 各成功部署增加 1；
- `explosive_packs_deployed` 各成功部署增加 1；
- 获取激光瞄准器不会写入任何 v0.5.1 字段。

## 8. 持久化与有界性

1. 产生统计后连续执行两次 `sm_lps_flush`，确认数值没有翻倍。
2. 正常换图后确认上一 Segment 关闭且设备明细仍可查询。
3. `sm_lps_status` 中确认设备关闭队列显示为 `pending_closed_equipment_stats=<数量>/4096`。
4. 数据库临时不可用时确认不生成逐事件日志或无限磁盘文件；恢复后绝对快照能够补写。

只读检查命令：

```powershell
python .\scripts\inspect_sqlite.py "<l4d2_player_stats.sq3 的完整路径>"
```

健康行应满足：`integrity=ok`，所有 `orphan_*`、`invalid_*` 和 `segment_run_mismatches` 均为 0。
