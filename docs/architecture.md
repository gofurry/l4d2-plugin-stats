# Monorepo architecture

```text
stats/
├─ collector/                 SourceMod collector source
│  ├─ src/                    single .sp entry point
│  └─ include/                compile-time .inc modules
├─ config/                    public configuration examples
├─ contracts/                 confirmed gameplay/data contracts
├─ database/
│  ├─ migrations/             canonical SQL migrations per driver
│  └─ schema.md               logical schema contract
├─ dashboard/                 Go API + Dashboard DB + embedded React UI
├─ docs/                      operator and development documentation
├─ scripts/                   build, validation, deploy, package tools
└─ dist/                      generated artifacts (ignored)
```

The collector source is modular but compiles into one plugin binary. Runtime
SQL migrations remain external files so the SQL stored in the repository is the
same SQL executed by SourceMod. Build artifacts never become source of truth.

The frozen Versus v1 boundary has three additional sources of truth:

```text
contracts/versus-v1.md                       field semantics and reader rules
contracts/versus-schema-v1.json              exact tables, columns, primary keys
database/queries/versus_contract_checks.sql  portable data invariants
```

The build validates the machine-readable manifest against all three migrations.
Future Go code consumes these contracts but remains read-only and does not own a
second migration history.

The dashboard has two deliberately separate storage boundaries:

```text
StatsStore (SQLite/MySQL/PostgreSQL, read only)
  └─ collector-owned identities, sessions, runs, rounds, segments and statistics

DashboardStore (embedded-migration SQLite, read/write)
  └─ site settings, footer links and the administrator-managed server directory
```

Three dialect-specific Stats query packages and one Dashboard query package are generated by sqlc. Business code depends only on common Store DTOs/interfaces. Goose migrates only Dashboard SQLite; the service merely checks `lps_schema_migrations` before reading Stats DB.

In development, Vite serves React on `127.0.0.1:10086` and proxies `/api` to Fiber on `127.0.0.1:18848`. In production, `dashboard/web/dist` is embedded and Fiber serves both SPA and API from port `18848`. A2S is a server-side provider restricted to enabled servers registered in Dashboard DB, with timeout, bounded concurrency, per-server cache and recent-success fallback. Each Dashboard server has a backend-generated UUID and one `host:port` address shared by the Steam join link and A2S query. Every enabled server has equal display priority; ordering is controlled only by `sort_order`.

Local machine paths belong in ignored `scripts/config.local.ps1`. Database
credentials belong only in the server's SourceMod `databases.cfg`.
