# v0.5.2 PvE 互动与状态测试清单

本清单用于验收目标互动、弹药堆补给、倒地/挂边时长和黑白队友恢复。

## 0. 测试前重建数据库

v0.5.2 仍处于未发布阶段，直接扩展了 `0001_initial.sql`。旧 SQLite 已记录迁移版本 1，不会自动获得新列。

1. 完全关闭游戏。
2. 备份或删除 `addons/sourcemod/data/sqlite/l4d2_player_stats.sq3`。
3. 重新构建并部署插件与迁移。
4. 启动本地 `coop`，确认 `sm_lps_status` 显示 `version=0.5.2`、`state=ready`、`schema=1/1`。

## 1. 自动验证

在仓库根目录执行：

```powershell
.\scripts\build.ps1
python .\scripts\test_sqlite_migration.py
```

预期 SourcePawn 无 error/warning，三种迁移通过检查，SQLite 显示 19 statements、12 tables、7 indexes。

## 2. 成功目标互动

在官方或训练地图完成至少两个不同的按钮、持续使用或旋转机关，然后执行：

```text
sm_lps_flush
```

验收：

- 每个成功完成的白名单实体使操作者 `objective_interactions +1`；
- 同一实体在同一 Round 重复触发仍只增加 1；
- 未完成持续使用、取消互动、普通开门和单纯按使用键不增加；
- 换到新 Round 后实体去重状态重新开始；
- Bot 完成或无法确定真人 activator 时不转移给房主。

白名单以[统计口径契约](../contracts/statistics.md#512-目标互动补给和失能时长)为准。

## 3. 弹药堆补给

1. 消耗主武器弹药。
2. 从地图弹药堆实际补充一次。
3. 再次消耗并补充一次。
4. 执行 `sm_lps_flush`。

预期 `ammo_pile_uses=2`。捡枪、部署升级弹药包和没有触发实际补给的使用动作不应增加。

## 4. 倒地与挂边时长

分别制造一次约 10 秒的普通倒地和约 10 秒的挂边，再被救起并刷新：

- `incapacitated_seconds` 只增加普通倒地时间；
- `ledge_hanging_seconds` 只增加挂边时间；
- 两项不应在同一时间段同时增长；
- 人工计时与数据库允许约 1～2 秒事件/操作误差；
- 状态持续中执行一次 flush，数秒后再 flush，第二次只增加新经过的完整秒数；
- 连续两次立即 flush 不应让时长翻倍。

死亡、被救起、离开真人幸存者 Segment 或回合结束都必须停止对应计时。

## 5. 黑白队友恢复

让另一名幸存者进入黑白状态，再由真人玩家对其完整使用医疗包：

- 成功恢复彩色后，施救者 `black_white_teammates_restored +1`；
- 被治疗者是真人或 Bot 均可，但统计只归属施救真人；
- 自己给自己打包不增加；
- 治疗普通彩色队友不增加；
- 治疗中断、换目标或没有真正解除黑白状态不增加。

## 6. 模式、Segment 与幂等性

1. 在 `coop` 或 `realism` 产生上述数据并刷新。
2. 连续执行两次 `sm_lps_flush`，确认计数不翻倍。
3. 正常换图后确认旧 Segment 关闭，新数据进入新 Segment。
4. 切到不支持模式时确认不创建统计。
5. `versus` 当前不应把这些字段写入 PvE 表；对抗统计留到 v0.6.0。

只读检查：

```powershell
python .\scripts\inspect_sqlite.py "<l4d2_player_stats.sq3 的完整路径>"
```

健康结果应满足 `integrity=ok`，所有 `orphan_*`、`invalid_*` 和 `segment_run_mismatches` 均为 0。

## 7. v0.5.x 尚需人工覆盖的分支

如果 v0.5.1 中以下动作还没有真实触发过，建议与本版一起补测：

- 四类控制的持续时间，以及另一名真人完成团队解救；
- 本人近战断舌与枪械空爆 Tank 石头；
- Witch 一击、单人击杀和多人共同参与；
- Tank/Witch 击杀参与；
- 燃烧/高爆弹药升级包部署；
- Molotov、Pipe Bomb、Vomit Jar 各自的 `actions` 与可归属击杀/伤害；
- 多种第三方枪械始终只生成一个 `Other Firearm` 行；
- 临时数据库故障后的关闭快照补写和队列上限行为。

本地单人无法完整证明“另一名远端真人解救”和数据库故障期间真人断线；这两项保留到 v0.7.0 多人/发布加固验收。
